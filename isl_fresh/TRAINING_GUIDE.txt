Complete guide for training the VideoMAE-based ISL translation model.
"""

# =============================================================================
# COMMAND LINE ARGUMENTS
# =============================================================================

--preset                 Hyperparameter preset
                        Choices: ['default', 'fast', 'production']
                        Default: 'default'
                        
                        'fast': Quick training (20 epochs, smaller model)
                                - Good for testing/debugging
                                - Decoder: 4 layers
                                - Batch size: 32 (effective)
                        
                        'default': Balanced training (100 epochs)
                                  - Good starting point
                                  - Decoder: 6 layers
                                  - Batch size: 32 (effective)
                        
                        'production': Best quality (150 epochs)
                                     - Maximum performance
                                     - Decoder: 8 layers
                                     - Batch size: 36 (effective)

--video-dir              Path to video directory
                        Default: Auto-detected (GPU or local)
                        Example: /path/to/iSign-videos_v1.1

--csv-path              Path to CSV metadata file
                        Default: Auto-detected (GPU or local)
                        Example: /path/to/iSign_v1.1.csv

--pretrained            Pretrained VideoMAE model
                        Default: 'MCG-NJU/videomae-base'
                        Options: Any HuggingFace VideoMAE model

--freeze-epochs         Number of epochs to keep encoder frozen
                        Default: 10
                        Range: 0-20
                        
                        Explanation: Transfer learning strategy
                        - Epochs 0-9: Only decoder trains (encoder frozen)
                        - Epoch 10+: Both encoder and decoder train
                        - Higher value = more conservative fine-tuning
                        - 0 = train everything from start (not recommended)

--num-frames            Frames per video clip
                        Default: 16
                        Note: Must match VideoMAE expectation (16)

--hidden-dim            Decoder hidden dimension
                        Default: 256
                        Range: 128-512
                        
                        Impact:
                        - Higher = more capacity, slower training
                        - 256 = good balance for most cases
                        - 384/512 = better for complex translations

--decoder-layers        Number of transformer decoder layers
                        Default: 4 (fast), 6 (default), 8 (production)
                        Range: 2-12
                        
                        Impact:
                        - More layers = better translation quality
                        - More layers = slower training, more memory
                        - 4 layers: ~7 hours/epoch (RTX 4060)
                        - 6 layers: ~10 hours/epoch
                        - 8 layers: ~14 hours/epoch


# =============================================================================
# TRAINING HYPERPARAMETERS
# =============================================================================

--epochs                Total training epochs
                        Default: 100
                        
                        Typical values:
                        - Quick test: 5-10
                        - Development: 50
                        - Production: 100-150

--batch-size            Batch size per GPU
                        Default: 16 (A100), 2-4 (RTX 4060)
                        
                        GPU Memory guide:
                        - RTX 4060 (8GB): batch-size 2, grad-accum 4
                        - RTX 3090 (24GB): batch-size 8, grad-accum 2
                        - A100 (40GB): batch-size 16, grad-accum 2
                        
                        Rule: Lower batch-size if OOM error

--gradient-accumulation Steps to accumulate gradients
                        Default: 2-4
                        
                        Effective batch size = batch-size × gradient-accumulation
                        
                        Example:
                        - batch-size 2 + grad-accum 4 = effective 8
                        - batch-size 4 + grad-accum 4 = effective 16
                        
                        Target effective batch: 16-32 for best results

--encoder-lr            Learning rate for encoder (VideoMAE)
                        Default: 1e-5
                        Range: 1e-6 to 5e-5
                        
                        Lower for pretrained models (recommended)
                        - Too high: destroys pretrained weights
                        - Too low: encoder doesn't adapt

--decoder-lr            Learning rate for decoder
                        Default: 3e-4
                        Range: 1e-4 to 5e-4
                        
                        Higher than encoder (decoder is random init)
                        - Standard Adam LR for transformers

--warmup-steps          Linear warmup steps for LR scheduler
                        Default: 2000
                        Range: 500-4000
                        
                        Explanation:
                        - LR increases linearly from 0 to max
                        - Prevents early training instability
                        - Higher for larger datasets
                        - ~2% of total training steps is good

--ctc-weight            Weight for CTC loss in hybrid loss
                        Default: 0.3
                        Range: 0.1-0.5
                        
                        Hybrid loss = (1-ctc_weight)×CE + ctc_weight×CTC
                        - 0.3 means 70% cross-entropy, 30% CTC
                        - CTC helps with alignment/streaming
                        - Higher CTC = better real-time performance


# =============================================================================
# EARLY STOPPING
# =============================================================================

--patience              Early stopping patience (epochs)
                        Default: 15
                        Range: 5-20
                        
                        How it works:
                        - Monitors validation loss each epoch
                        - If loss doesn't improve for N epochs, stop training
                        - Prevents overfitting and saves time
                        
                        Example:
                        Epoch 20: val_loss = 2.5 (best so far) ✓
                        Epoch 21: val_loss = 2.6 (worse, patience 1/15)
                        Epoch 22: val_loss = 2.7 (worse, patience 2/15)
                        ...
                        Epoch 35: val_loss = 2.8 (worse, patience 15/15) → STOP
                        
                        Final model = checkpoint from Epoch 20
                        
                        Recommendations:
                        - Small datasets: patience 5-10
                        - Large datasets: patience 15-20
                        - If loss is noisy: increase patience


# =============================================================================
# SYSTEM CONFIGURATION
# =============================================================================

--num-workers           Data loading worker processes
                        Default: 4
                        Range: 0-8
                        
                        0 = single process (slower but stable)
                        4 = good for most systems
                        8 = high-end CPUs only
                        
                        Note: Use 0 if seeing multiprocessing errors

--checkpoint-dir        Directory to save checkpoints
                        Default: 'checkpoints_video'

--log-dir              Directory for TensorBoard logs
                        Default: 'logs_video'

--experiment-name      Name for this training run
                        Default: 'videomae_transfer'
                        
                        Used in logs and checkpoint names

--resume               Resume from checkpoint
                        Default: None
                        Example: --resume checkpoints_video/best.pt

# =============================================================================
# LIVE TRANSLATION / REAL-TIME INFERENCE
# =============================================================================

YES, this model CAN be used for live translation! Here's how:

1. Model Architecture Advantages:
   - VideoMAE processes 16-frame clips (~0.5 sec of video)
   - CTC loss enables streaming decoding
   - No dependency on full video length

2. Real-time Pipeline:
   
   Camera → Buffer → Process → Translate → Display
   
   Step 1: Capture video stream
   Step 2: Maintain 16-frame sliding window buffer
   Step 3: Process every N frames (e.g., every 8 frames = 50% overlap)
   Step 4: Model translates current clip
   Step 5: Display/speak output

3. Implementation:
   
   import cv2
   import torch
   from collections import deque
   
   model = ISLTranslator.load('checkpoint_best.pt')
   model.eval()
   
   frame_buffer = deque(maxlen=16)
   cap = cv2.VideoCapture(0)  # Webcam
   
   while True:
       ret, frame = cap.read()
       frame_buffer.append(frame)
       
       if len(frame_buffer) == 16:
           # Process 16 frames
           video_tensor = preprocess_frames(list(frame_buffer))
           translation = model.translate(video_tensor)
           print(translation)  # Or display on screen
           
           # Slide window by 8 frames for next prediction
           for _ in range(8):
               frame_buffer.popleft()

4. Latency:
   - Processing: ~50-100ms per clip (GPU)
   - Total latency: ~200-300ms (real-time!)
   - Can be optimized with TensorRT/ONNX

5. Mobile Deployment:
   - Use quantize_for_mobile.py to reduce model size
   - 400MB → 100MB with quantization
   - Can run on mobile GPU (slower but feasible)

# =============================================================================
# TROUBLESHOOTING
# =============================================================================

Problem: CUDA Out of Memory (OOM)
Solution: 
  - Reduce batch-size (e.g., 16 → 8 → 4 → 2)
  - Reduce decoder-layers (e.g., 6 → 4)
  - Reduce hidden-dim (e.g., 256 → 128)
  - Increase gradient-accumulation to maintain effective batch size

Problem: Training too slow
Solution:
  - Increase batch-size if memory allows
  - Reduce num-workers if CPU bottleneck
  - Use --preset fast for testing
  - Train on A100 GPU instead of laptop

Problem: Loss not decreasing
Solution:
  - Check learning rates (encoder-lr, decoder-lr)
  - Increase warmup-steps
  - Check data quality (videos loading correctly?)
  - Try different ctc-weight (0.2-0.4)

Problem: Overfitting (val loss increases)
Solution:
  - Early stopping will handle this automatically
  - Reduce decoder-layers
  - Add more data
  - Check patience setting

Problem: Multiprocessing errors
Solution:
  - Set --num-workers 0 (use single process)
  - Windows has issues with multiprocessing in PyTorch
